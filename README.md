# muscle-log

筋トレ記録アプリ。iOS / Android 両対応、**オフラインで動作**（記録はスマホ本体に保存され、通信は一切不要）。

## 作るもの（MVP）

1. **トレーニング記録** — 種目・重量・レップ数・セット数を入力 / 編集 / 削除
2. **履歴の一覧** — 日付順に並び、タップで詳細を表示
3. **前回コピー + 次の種目の提案** — 前回メニューをワンタップで複製。さらに過去の傾向から「この種目の次によくやる種目」を提案

## 技術構成と役割

| 層 | 使うもの | 役割（何をするもの？） |
|---|---|---|
| 言語 | TypeScript | アプリの動きを書く言語。JavaScript に「型」を足したもので、書き間違いをエディタが指摘してくれる |
| フレームワーク | React Native + Expo (SDK 54) | 1つのコードから iPhone / Android 両方のアプリを作る仕組み。Expo はその面倒な設定を肩代わりしてくれる道具箱 |
| 画面遷移 | Expo Router | `app/` にファイルを置くだけで画面とURLが決まる仕組み |
| データベース | SQLite (`expo-sqlite`) | スマホ本体の中に記録を保存する小さなDB。**オフライン動作の鍵** |
| DB操作 | Drizzle ORM (`drizzle-orm` / `drizzle-kit`) | SQL を TypeScript から型安全に書く道具。テーブル定義から実際の CREATE TABLE 文（マイグレーション）を生成してくれる |

### なぜこの構成か

- **サーバーを使わない** — 記録はすべて端末内の SQLite に保存する。ジムの地下で電波が入らなくても動くし、サーバー代は 0 円、ユーザー登録も不要。将来クラウド同期したくなったら、この上に足す形で拡張できる。
- **言語が TypeScript 1本** — iOS 用 / Android 用に別々の言語を覚える必要がない。Web 上の情報量が多く、詰まったときに調べやすい。
- **Expo Go で実機確認できる** — Windows PC でも、iPhone にアプリを入れずに手元の実機で動作を確認できる（後述）。

> **SDK バージョンについて**: Expo Go アプリは1つのバージョンにつき対応する SDK が1つに決まっており、プロジェクトの SDK と一致しないと実機で開けない。このプロジェクトは SDK 54 を使っているが、これは「最新」だからではなく、**手元の iPhone に入っている Expo Go アプリが対応する SDK が 54 までだったため**、それに合わせて選んでいる。Expo Go 側が新しい SDK に対応した後にプロジェクトを最新化したくなったら、`npx expo install --fix` で一括アップグレードできる。

```

│   ├── index.tsx            ホーム = トレーニング履歴の一覧          →  /

│       ├── [id].tsx         トレーニング詳細（[id] は可変部分）      →  /workout/1, /workout/42 ...
│       └── [id]/
│           └── edit.tsx     記録の編集画面                          →  /workout/1/edit
│
├── src/                     ★ 画面以外のロジック置き場
│   ├── db/
│   │   ├── schema.ts        テーブル定義（workout / exercise_entry / set_entry）
│   │   ├── client.ts        SQLite への接続と drizzle インスタンスの作成
│   │   └── queries.ts       ★ CRUD 関数群。画面はここを経由してのみ DB に触る
│   ├── components/
│   │   └── WorkoutForm.tsx  記録の入力・編集で共通して使うフォーム部品
│   └── theme/
│       └── colors.ts        アプリ全体の色定義。色コードの直書きはせずここを経由する
│
├── drizzle/                 ★ 自動生成されるSQLマイグレーション（手で編集しない）
│   ├── 0000_xxx.sql         実際に実行される CREATE TABLE 文
│   ├── migrations.js        上記をアプリに読み込ませるためのファイル
│   └── meta/                drizzle-kit の管理用メタデータ
│
├── assets/                  アイコンやスプラッシュ画像
├── app.json                 アプリ名・アイコン・プラグインなどの設定
├── package.json             依存パッケージと npm スクリプト
├── drizzle.config.ts        drizzle-kit の設定（スキーマの場所、出力先など）
├── metro.config.js          .sql ファイルをバンドル対象にするための設定
├── babel.config.js          .sql ファイルを文字列として import できるようにする設定
└── tsconfig.json            TypeScript の設定
```

### `app/` の命名ルール（Expo Router）

| ファイル名 | 意味 |
|---|---|
| `index.tsx` | そのフォルダの「トップ」画面 |
| `_layout.tsx` | 配下の画面すべてを包む枠。アンダースコア始まりは画面にならない |
| `[id].tsx` | 角括弧は「ここは可変」。`/workout/1` でも `/workout/42` でもこの画面が開く |

```
└───────┬─────────────┬───┘
        │             │

        │             │
        ▼             ▼
┌──────────────┐  ┌──────────────┐
│ /workout/1   │  │ /workout/new │
│ 詳細          │  │ 記録の入力     │
└──────┬───────┘  └──────────────┘
       │

       │
       ▼
┌───────────────────┐

│ 記録の編集           │
└────────────────────┘
```

**現在の状態**:

- ホーム（履歴一覧）… SQLite から実データを読んで表示する
- 記録の入力・編集… 種目とセットを複数追加しながら入力でき、保存すると DB に書き込まれる（新規作成・編集で同じフォームを共用）
- トレーニング詳細… 実データ（種目・セット）を表示し、編集・削除ができる

## データ設計

SQLite に作った3テーブル。定義は [src/db/schema.ts](src/db/schema.ts)。

```
workout（1回のトレーニング = 1日分）
  id, date（'YYYY-MM-DD'）, memo
   │
   └─ exercise_entry（その日にやった種目。sort_order で表示順を保持）
        id, workout_id, name（種目名を直接持つ）, sort_order
         │
         └─ set_entry（1セットごとの記録）
              id, exercise_entry_id, weight, reps, set_number
```

**セットを独立した行にするのが要点。** こうしておくと「3セット目だけ重量を落とした」といった現実的な記録がそのまま入り、後から「ベンチプレスの最大重量の推移」のようなグラフも作れる。

**種目マスタは作らず、`exercise_entry.name` に種目名を直接文字列で持つ**シンプルな構成にした（当初案では種目を別テーブルに分ける設計も検討したが、まずは最小構成で始める）。「次の種目の提案」もこの文字列の集計で実現できるため、現時点では困らない。

親（workout）を削除すると、紐づく exercise_entry・set_entry も自動的に削除される（外部キーの `ON DELETE CASCADE`）。

### マイグレーションの仕組み

`src/db/schema.ts` を変更したら、次のコマンドで SQL 差分ファイルを生成する。

```powershell
npx drizzle-kit generate
```

生成された `drizzle/*.sql` はアプリ起動時に [app/_layout.tsx](app/_layout.tsx) の `useMigrations` フックが自動で適用する。手で `CREATE TABLE` を書いたり、既存の `.sql` ファイルを直接編集したりはしない。

## 「次の種目の提案」の仕組み

> 現状、記録の入力フォームには「よく使う種目」の候補チップ（`listFrequentExerciseNames`、使用回数が多い種目名をそのまま表示）だけが実装済み。これは種目名入力の手間を減らすための単純な頻度集計で、以下で説明する「順番に基づく次の種目提案」とは別物（未実装）。

**AI や機械学習は使わない。** 過去データの数え上げだけで実現する。

同じワークアウト内で「順番が隣り合う種目のペア」を全履歴から数え、多い順に提案する。

```
ベンチプレス → インクラインプレス   12回   ← 提案1位
ベンチプレス → チェストフライ         7回   ← 提案2位
ベンチプレス → トライセプス           3回
```

これは `exercise_entry` を `sort_order` で自己結合する SQL 一発で出せる。
履歴が少ないうちは結果が出ないので、その場合は「よく使う種目トップ5」にフォールバックする。（未実装。実装の進め方の #7）

## 起動と動作確認の手順

### 前提

- Node.js（インストール済み: v24）
- スマホ（iPhone / Android どちらでも可）
- **PC とスマホが同じ Wi-Fi に繋がっていること**

### 1. スマホに Expo Go を入れる

- iPhone: App Store で「**Expo Go**」を検索してインストール
- Android: Google Play で「**Expo Go**」を検索してインストール

Expo Go は「開発中のアプリを読み込んで動かすための入れ物アプリ」。
これのおかげで、Mac がなくても iPhone で動作確認できる。

### 2. 開発サーバーを起動する

PowerShell で：

```powershell
cd "c:\Users\kouki\OneDrive - MeijiMail\アプリ\muscle-log"
npm start
```

ターミナルに QR コードが表示されれば成功。

### 3. スマホで読み込む

- **iPhone**: 標準の**カメラアプリ**で QR コードを写す → 出てくるバナーをタップ
- **Android**: **Expo Go アプリ**を開き、「Scan QR code」で読み取る

数十秒待つとアプリが立ち上がる。

### 4. 動作確認のチェックリスト

- [ ] 起動直後に一瞬「準備中...」と出て（DB のテーブル作成中）、その後「トレーニング履歴」の一覧が表示される（初回は「まだ記録がありません」）
- [ ] 右下の「＋ 記録する」→ 「記録を追加」画面に遷移する
- [ ] 日付の左右の ◀ ▶ で日付が変わる（タップした日付部分をタップすると今日に戻る）
- [ ] 「＋ 種目を追加」で種目カードが増える。種目名を空にすると、よく使う種目の候補チップが出る（初回は候補なし）
- [ ] 種目名・重量・レップ数を入力し、「＋ セットを追加」でセットが増える（直前のセットの値が初期値として引き継がれる）
- [ ] 「保存する」→ 一覧に戻り、保存した記録がカードとして表示される
- [ ] カードをタップ → 「トレーニング詳細」に遷移し、種目名・セットごとの重量とレップ数が表示される
- [ ] 詳細画面の「編集する」→ 入力済みの内容がフォームに反映された状態で開く。内容を変更して「更新する」→ 詳細画面に戻り、変更が反映されている
- [ ] 詳細画面の「削除する」→ 確認ダイアログ →「削除する」→ 一覧に戻り、その記録が消えている
- [ ] ヘッダー左の戻るボタンで一覧に戻る

ここまで動けば、記録の作成・一覧・詳細・編集・削除がひと通り動く状態。

### 実機の中のデータを完全にリセットしたい場合

DB は端末（または Expo Go）側に保存されているため、コードを直しただけでは消えない。次のどちらかで空の状態からやり直せる。

- Expo Go アプリの中でこのプロジェクトを長押し →「Clear cache」などでプロジェクトデータを消す
- 端末の設定から Expo Go アプリのデータを削除する

### PC だけで確認したい場合

実機なしでも、Android Studio のエミュレータがあれば `npm run android` で起動できる。
未インストールなら、まずは Expo Go を使う方法を推奨。

## つまずいたときは

| 症状 | 対処 |
|---|---|
| QR を読んでも繋がらない | PC とスマホが**同じ Wi-Fi** か確認。ダメなら `npm start -- --tunnel` |
| 画面が真っ白 / 変な挙動 | `npm start -- --clear` でキャッシュを消して再起動 |
| ファイルを変えても反映されない | 同上。それでもダメならサーバーを Ctrl+C で止めて再起動 |
| `npm install` で `EPERM`、`node_modules` の削除に失敗する | OneDrive 同期との競合が疑わしい（下記「OneDrive についての注意」を参照。ジャンクションの張り直しが必要な場合あり） |
| QR を読んだら「Expo Go の SDK バージョンが一致しません」と出る | Expo Go アプリを最新に更新する。更新できない（対応 SDK が上がらない）場合は、プロジェクト側を Expo Go が対応する SDK に合わせて downgrade する（`package.json` の `expo` を該当 SDK のバージョンに変更 → `npx expo install --fix`） |
| `schema.ts` を変更したのに反映されない | `npx drizzle-kit generate` を忘れていないか確認。生成後はアプリを再起動する |
| DB 関連のエラーで「準備中...」から進まない | 一度アプリを完全に終了して再起動。それでも直らなければ実機のデータをリセット（後述） |

### OneDrive についての注意

このプロジェクトは OneDrive の同期フォルダ内にあるが、**`node_modules` の実体は OneDrive 管理外**に置いてある。

```
プロジェクト内の node_modules/  ← これはジャンクション（実体への案内板のようなもの）
  └─ 実体: C:\dev-cache\muscle-log\node_modules  ← ここに数万ファイルが置かれる。OneDrive は同期しない
```

`node_modules` は数万ファイルあり、OneDrive の同期と npm の書き込みが同時に起きると、
Windows がファイルを「使用中」と誤認して `EPERM` エラーになったり、削除が中途半端に失敗したりすることがある。
その対策として、`node_modules` だけを OneDrive の外（`C:\dev-cache\muscle-log`）に逃がしてある。

**この構成での注意点:**

- `npm install` はいつも通り実行するだけでよい。ジャンクション越しに `C:\dev-cache\muscle-log\node_modules` へ書き込まれる
- `Remove-Item node_modules -Recurse -Force` を実行すると、消えるのは**プロジェクト側のジャンクション（案内板）だけ**。`C:\dev-cache\muscle-log\node_modules` の中身はそのまま残る（Windows PowerShell の仕様）。中身ごと完全に消したいとき（依存関係が大きく壊れた時など）は、実体側も明示的に消す:

  ```powershell
  Remove-Item node_modules -Force -ErrorAction SilentlyContinue                          # ジャンクションを消す
  Remove-Item "C:\dev-cache\muscle-log\node_modules" -Recurse -Force -ErrorAction SilentlyContinue  # 実体を消す
  New-Item -ItemType Directory -Path "C:\dev-cache\muscle-log\node_modules" -Force
  New-Item -ItemType Junction -Path "node_modules" -Target "C:\dev-cache\muscle-log\node_modules"
  npm install
  ```

- **`C:\dev-cache` フォルダは Git にも OneDrive にも含まれない。** 別の PC でこのプロジェクトを開いた場合や、`C:\dev-cache` を手動で消してしまった場合は、ジャンクションが指す先を失うので `npm install` がエラーになる。そのときは上のコマンドで作り直す

なお `node_modules` は `.gitignore` 済みなので、Git のリポジトリには（ジャンクションかどうかによらず）含まれない。
